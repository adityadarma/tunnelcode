# ADR-005

## ORM

Decision

Drizzle ORM.

Migrations must never destroy existing data.

Every migration is additive:

- add a table
- add a nullable column
- add a column with a default
- add an index

Not allowed without explicit approval:

- drop a table
- drop a column
- rename a table or column
- change a column type
- add a NOT NULL column without a default

Migrations are append only. A migration that has shipped is never edited, a new
one is added instead.

Reason

Type-safe.

Simple migrations.

Conversations are the only thing the user cannot recreate, so a schema change
must never be able to lose them.

# ADR-014

## Authentication

Decision

No user authentication in the MVP.

Pairing uses an 8 letter pairing code (A-Z) plus a 4 digit approval number.

The code is generated in uppercase.

Matching is case sensitive.

The approval number is generated by the server after the code is accepted.

The browser shows the approval number.

The CLI shows the same number and waits for the user to approve.

Only the CLI can approve a pairing request.

The pair endpoint is rate limited.

The code is valid while the CLI session is running.

The code is single use.

The session expires after 1 hour without conversation.

Once expired the CLI exits and the code cannot be used again.

Reason

MVP focus.

The code does not need to be stored permanently.

The code travels in a query string, so a leaked URL must not be enough to pair.

The approval number never travels in a URL.

# ADR-017

## Turn Lifetime

Decision

A turn outlives the browser socket that started it.

The attach reply reports the turn still running, when there is one.

The CLI abandons a turn after 5 minutes of engine silence.

Silence is measured between engine events, never over the whole turn.

An abandoned turn is reported as an error, never as a finished answer.

Reason

A refresh closes the socket without ending the turn. The agent runs on the paired
machine, so ending it on refresh would throw away work already in progress.

The browser has no other way to learn an answer is already on its way, and would
otherwise offer a composer whose next prompt is certain to be refused.

A device answers one prompt at a time, so an engine that hangs holds the device
until the CLI is restarted.

A long task that keeps streaming is working as intended. Only silence indicates
an engine that is not coming back.

Deltas are not stored, so an answer streamed while no browser was attached cannot
be recovered. Waiting for the turn to finish is what restores it.
